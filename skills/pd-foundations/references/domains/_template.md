# <Domain> domain pack

Copy this file to `domains/<domain>.md`, fill each section, and list the pack in `domain_packs` in
`PROJECT.md`. Keep it to rules a capable designer would not already know; skip generic UX advice.

## Context

Who the users are, the setting they work in (time pressure, devices, environment), what is at stake
when the design fails (clinical, legal, financial, safety), and what kinds of products this pack covers.

## Regulatory regime

Which laws or standards apply, in which jurisdictions, and what each means for the UI. Name the
regime precisely (for example the statute, not "privacy rules") and say which parts you are unsure of.
If a pillar should activate in `compliance.md`, say so here.

## Rules

Domain-specific UI rules, grouped by theme (data handling, consent, error prevention, status, workflow
patterns). Each rule gets a one-clause reason so a model can generalize to cases the rule didn't list.
